# Codex 用リポジトリコンテキスト

この文書は `AGENTS.md` に入れるほど常時必要ではないが、Elin Mod の設計・調査時に知っておくと判断精度が上がる背景をまとめる。

## 開発スタイル

- Mod は「必要な部分だけゲーム本体へ介入する」方針を基本とする。
- Harmony の Prefix / Postfix を無条件に Transpiler より優先するわけではない。
- Prefix / Postfix のために vanilla 実装を大きくコピーするくらいなら、限定的な Transpiler の方が追従しやすい場合がある。
- Transpiler は壊れないことだけを目標にせず、ゲームアップデートで前提が崩れたときに壊れたことを検出しやすい設計を好む。
- public API を提供すること自体を目的としたライブラリではないため、外部公開は必要性がある場合だけ行う。
- パフォーマンス判断は「毎フレームだから悪い」「Reflection だから悪い」のようなラベルではなく、実行頻度と実測値を重視する。

## Codex へ期待する役割

### 調査を頼まれた場合

- 関連コードを横断して根拠を集める。
- call site と state transition を追う。
- 推測と確認済みを分ける。
- まだ変更しない。

### 実装を頼まれた場合

- 必要な調査を行う。
- 最小限の変更で実装する。
- build と diff を確認する。
- ゲーム内確認が必要な箇所はテスト観点を提示する。

### レビューを頼まれた場合

- style の好みより、correctness、互換性、lifetime、performance、アップデート耐性を優先する。
- 問題がなければ無理に改善点を作らない。

## ドキュメント更新ルール

- 新しい恒久ルール → `AGENTS.md`
- Mod 固有の恒久ルール → 各 Mod の `AGENTS.md`
- 実測性能 → `performance-notes.md`
- vanilla 内部処理について再利用価値のある発見 → `elin-internals.md`
- 「なぜこの設計なのか」という判断 → `decision-log.md`
- 同じ調査手順を何度も使う → Skill 化
